信贷策略分析建模 SKILL / MCP 完备性复核

项目：credit_risk_agent · 复核日期：2026-11-11 · 范围：skills/、src/credit_agent/tools/、mcp_server.py、workbuddy/、tests/、docs/、打包与安装配置
状态说明：本报告是 2026-11-11 修复前的只读复核快照，文中引用的 docs/ 路径为当时的目录布局；历史设计稿现已移入 docs/archive/，问题已按 v0.3 修复，修复结果见 docs/skill-mcp-validation-2026-11-11.md 的复核章节。

修复前结论：接口骨架已开发完备，业务口径、治理闭环与部署就绪度尚未完备。
4 个 SKILL 与 11 个 MCP 工具一一对应，envelope 状态机、路径白名单、OOT 优先、特征审批闸门等核心机制均已落地且 142 项测试全绿。 但按「可对外交付、可上线、可审计」的标准，仍存在 7 项 P0 阻断项（含 3 处信贷业务红线/口径偏差、异常脱离契约、Connector 在当前环境无法启动、审批适配器缺失、账本边界）， 以及契约枚举、业务能力、发布规范与文档治理等 P1 项。当前定位应是本地试点原型，不宜作为准出版本。

二、P0：发布前必须修复的阻断项

P0-1拒绝推断红线：swap_in_bad_rate 未固定为「未知」

证据：src/credit_agent/tools/policy.py:218-219 把 swap["swap_in"]["bad_rate"] 原样写入摘要；src/credit_agent/analytics/strategy.py:254, 382-398 的 swap_in 是「已放款样本中未过现行阈值、但过候选阈值」的行，这些行本身带 bad 标记，因此 _outcome_block 会返回非空坏账率。

冲突：skills/policy-cutoff-simulation/SKILL.md:42, 99 要求 swap_in_bad_rate 固定为空、正文写「未知」；:29 是核心红线「严禁估算放宽后新增通过客群的真实坏账率」。实现给出的是「已放款样本跨阈值带」的实测坏账率，语义上极易被 Agent 误引用为「被拒客群调入集」的坏账率。

建议：在 simulate_policy_rules 层强制 swap_in_bad_rate = None；swap_in 只返回笔数；补齐 keep_rejected 块与「矩阵下半行不在样本内」声明；保留现有 caveat 但不输出数字。

P0-2规则挖掘默认扫描全表列，无决策时点字段门禁

证据：mcp_server.py:132-142 的 features 默认 None；policy.py:264, 270-274 直接透传；analytics/rules.py:31 的 feats = features or df.columns 在缺省时取全表列（仅排除 bad 与时间列）。simulate_policy_rules 从不读取 resolve_metric_and_dimensions 绑定的 decision 维度表，policy 实现中 TIME_POINT_VIOLATION / DIMENSION_UNREGISTERED 产生点为 0。

影响：贷后 DPD、催收、观察时点结果、标签衍生列都可能被挖成「拦截规则」，构成典型的目标穿越；SKILL :31, 55-56 的字段约束只靠 Agent 自觉遵守，工具层无防线。另 rules.py:55-58 只有覆盖率比例门槛、无 n ≥ 50 绝对命中量门槛，policy.py:188 的 trials 统计的是过滤后 TopN 而非总搜索候选数。

建议：features 设为必填并校验为绑定登记的 point_in_time=decision 维度子集；取消 mine_rules 的全表回退；补 min_hits 与真实 trials 统计；对越界字段返回对应 block_code。

P0-3成熟度判定用「批次月末 + W 月」，与 SKILL 的 T0 + W 口径不一致

证据：tools/admission.py:178-183 的 docstring 明确写「A cohort … is mature when its month-end plus W months is on or before the snapshot cutoff」；:214-227 完全按 cohort 标签解析月末计算，decision_time_column 在 :206-207 只做列存在性检查；FPD 天数窗口被 days/30 向上取整成月。

影响：SKILL :56 与 references/data-contract-and-windows.md:25-27 要求按每笔决策时点 T0 判断 T0 + W ≤ T_cutoff。当前算法方向偏保守（不会把未成熟误判为成熟），但会系统性低估可用成熟样本，且「FPD30 = 首期账单日后 30 天」被改写为「月末 + 1 月」，与已签收口径不符；摘要也未记录实际使用的 T0 与截止日供复核。

建议：按批次取 decision_time_column 的最晚 T0 计算成熟；日窗口与月窗口分别处理；在摘要写入实际 T0 列、截止日与判定依据。

P0-411 个 MCP 工具均无异常兜底，异常脱离 envelope 契约

证据：mcp_server.py:54-158 所有 @server.tool 函数体无 try/except。可达路径包括：文件不存在/非法后缀（:33-37）、口径 JSON/YAML 解析失败（:88-89）、registry 缺字段（admission.py:618-625）、无效 run_id（modeling_ops.py:312, 462、portfolio.py:170）、非法 mode（policy.py:256）、cutoff 缺 score/edges（policy.py:199）。尤其 modeling_ops.py:526-533 把小样本、类别单一等常见业务情形一律 raise ValueError。

影响：真实 MCP 调用实测返回 ToolError 文本而非 {status, block_code}，4 个 SKILL 的停机处置表对此完全失效；Agent 无法区分「文件不存在」「口径未签收」「需要人工」，容易重试或编造结论。

建议：在 create_server 统一包裹 tool 函数，把可预期异常映射为 blocked envelope 与明确 block_code；把 train_classifier 的各类 error 映射到 VALIDATION_UNAVAILABLE / BASELINE_UNAVAILABLE；自由形态 dict 参数改用 pydantic/TypedDict 生成强 schema。

P0-5Connector 在当前环境无法启动，打包器不做可导入性校验

实测：在项目根用 ../.venv/bin/python 执行 find_spec("credit_agent") → None，python -m credit_agent.mcp_server --help 报 ModuleNotFoundError；该 venv 已装 mcp、yaml，但安装的是另一个分发 credit-agent-tools，并非 credit-risk-agent-core。测试之所以全绿，是因为 tests/test_mcp_server.py:74 手工注入了 PYTHONPATH=src。

证据：workbuddy/build_connector.py:28-29 只校验 python 可执行文件存在，不校验 import credit_agent 与 mcp 依赖；生成的 mcp.json（:42-57）用 -m credit_agent.mcp_server 且无 env，cwd 指向项目根对 src/ 布局无效（包必须已安装）。

影响：按当前状态生成的 Connector 导入 WorkBuddy 后会启动失败且不易诊断；文档「安装到同一 Python 环境」是隐含前置条件，缺少强制校验。另 mcp_server.py:15 顶层 import yaml，而 PyYAML 只在 [mcp] extra（pyproject.toml:25），导致 :45 的友好提示不可达。

建议：打包器增加 python -c "import credit_agent, mcp, yaml" 预检；把 PyYAML 提升为核心依赖或延迟导入；修正/移除误导性 cwd；文档把 pip install -e '.[mcp]' 写成硬前置。

P0-6人工审批闭环未交付，且 3 个 gate「只写不读」

证据：tools/evidence.py:15, 40-64 定义 5 个 gate，但 get_decision 全库调用点仅 modeling_ops.py:145, 467 与 policy.py:281（validation_fallback / feature_list）。anomaly_disposition、policy_trial、model_signoff 无任何工具层消费；模型卡状态在 modeling_ops.py:447 硬编码 "status": "candidate"，从不检查签收。

影响：SKILL portfolio:71、policy:62、scorecard:67, 128 要求这些 gate 决定能否立项/签收/写「已批准」，实际只靠 Agent 自觉遵守文本。叠加「宿主审批卡适配器未提供」（文档已披露），所有 needs_human 回退路径在 WorkBuddy 中无法闭环，训练停在 FEATURE_REVIEW_REQUIRED。

建议：提供一个参考宿主适配器（把审批卡写入同一 ledger 的受信任接口）；在处置立项、试验签收、报告提交路径读取决定并据此放行或停 needs_human；模型卡状态由 model_signoff 决定。

P0-7账本边界与审计属性不足

证据：mcp_server.py:47-51 对 data_root/registry_root 做 resolve(strict=True) + is_dir()，唯独 ledger_root 直接传入且未校验与另两个根互不相交。若管理员把账本放在数据根子目录，list_credit_datasets 的 rglob（:57-59）会把 ledger/frames/*.parquet（ledger.py:67-69 保存的完整明细）列为可用数据集，Agent 可绑定读取，绕过准入与成熟度闸门。

其它：目录/文件未设 0o700/0o600；save_frame/load_frame/save_run 用外部 id 直接拼路径（ledger.py:68, 73, 150, 176）且无白名单；decisions 表 PRIMARY KEY(gate, review_id) + INSERT OR REPLACE（:55-58, 180-186），无时间戳、无 consumed 标记，同一确认单可无限重放、payload 可被覆盖；无 tenant 命名空间，任一会话拿到他人 run_id 即可读摘要与帧。

建议：启动时断言三个根目录两两互不相交并统一 resolve/权限检查；id 加白名单并 is_relative_to 校验；确认单改为追加只写 + 一次性消费标记；按租户分库分进程，或由宿主注入受信任 tenant 上下文。

三、P1：契约一致性与业务能力缺口

P1-A阻断码双向不一致

  • DIMENSION_UNREGISTERED：两个 SKILL 声明，tools/ 全目录 0 处产生。
  • TIME_POINT_VIOLATION：3 个 SKILL 声明，仅 portfolio.py:215 产生（且因 binding 已过滤为 decision-only，正常配置下不可达）；policy / modeling 无产生点。
  • 实现返回 VALIDATION_CHOICE_REQUIRED、USER_CHOSE_STOP（policy.py:279, 288、modeling_ops.py:137-149），4 个 SKILL 码表均未列；policy 用 RANDOM_SPLIT_FORBIDDEN、portfolio 用 SNAPSHOT_INVALID 属跨 SKILL 串码。
  • portfolio 的 LABEL_IMMATURE 实际由 ADMISSION_REQUIRED 代替。

建议：抽 tools/codes.py 单一枚举，加「SKILL 声明码 ⊆ 代码常量」的回归测试，统一码表后再版 SKILL。

P1-B摘要契约字段与 SKILL / 引证工具错位

  • modeling_ops.py:249 返回扁平 split_method，SKILL :63 要求 citation path: split.method → evidence.py:67-79 取不到值。
  • modeling_ops.py:387-410：返回给 Agent 的 public.selected 是字符串列表，落账 saved.selected 是 dict 列表；verify_and_commit_report 校验的是落账 summary，按可见摘要写引用会因非数字被 REPORT_UNTRACED。
  • evidence.py:17-28 数字正则无纯整数分支（「共 2000 笔」不进入未引用检查），而 :82-87 的 _is_number 拒收字符串，导致 SKILL credit-data-admission:60 要求「日期也提交 citations」时反而必然失败。
  • admission.py:246 的 mask_id 直接等于 snapshot_id，与 SKILL 暗示的独立掩码标识不符。

P1-C策略能力未交付完整

  • 模式 C 盈亏平衡：economics 只在库函数签名（policy.py:242），MCP 未暴露；_economics_caveat（:120-130）只返回一句 caveat，不计算各档边际期望净收益、不标注 r_break-even 建议切点（SKILL :73-75, 91）。
  • Swap Set 只有 3 块，缺 keep_rejected；缺激进/平衡/温和三档候选与《冠军挑战者试验设计单》（SKILL :94-107）。
  • inspect_and_bind_snapshot 的 weight_column 只登记不使用（admission.py:98-99, 152），下游权重来自 metric 绑定。

P1-D登记维度与阈值被硬编码/静默替换

  • portfolio.py:160-165, 517-567 从 binding 读出的维度 spec 只取 column/point_in_time，登记表的 max_cardinality / min_cell_n / bins / cut_points 全部丢弃；下钻一律用全局 min_n=50, min_events=5。SKILL 要求「事先登记的固定分档刀口」。
  • min_n / min_events / contribution_floor / alpha / min_iv / max_feature_psi / max_features / random_state 均未在 MCP 暴露。
  • base_periods / comp_periods MCP 声明可省略（mcp_server.py:94-96），SKILL :59 要求必填；省略会抛异常，期次不匹配时 analytics/windows.py:27-33 静默回退「最后 3 期 vs 之前」，用户指定期次被丢弃。
  • portfolio.py:97-105, 339 部分视图缺列或不可比时仍返回 ok；closure_error（:257）只展示不校验，reference 要求 < 1e-9。
