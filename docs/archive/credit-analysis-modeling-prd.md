# 信贷风控产品需求：存量监控归因，以及建模回测

日期：2026-11-02。状态：待确认。确认前不写业务前端、不改路由、不把计算库接成工具。

上一稿把本阶段收成「一次性分析 + 模型研究」，并排除了监控和策略回溯。按本次决定，那一稿作废。本文只覆盖下面两个并列的一级产品。

依据：`credit_risk_agent/docs/CREDIT_AGENT_PRODUCT_DESIGN_V3.md` 的诊断、策略比较、模型研究和监控，以及 `credit_risk_agent/src/credit_agent` 里已经能算的迁徙、下钻、结构分解和建模步骤。

## 1. 这是什么产品

两个给中小机构风控团队用的 Agent。团队常常只剩 1 到 2 个人，活没有变少。产品帮他们盯住已经放出去的资产，并加快模型与策略试验，而不是帮机构多批单。

| 产品 | 给谁 | 价值 |
| --- | --- | --- |
| 存量资产监控与风险归因 | 风控、贷后、策略负责人 | 更早发现资产恶化，提前处置，减少坏账损失 |
| 风控建模与回测自动化 | 同一批分析师，作为助手 | 用更少人力完成分箱、KS/PSI、筛选、回测、对比和版本记录 |

两者共用同一套数据集、口径和课题记录，各有自己的 Agent。业务前端新建，不改 `/app`。`/app` 仍只演示通用框架。运行、身份、暂停和恢复用现有 harness。计算调用 `credit_agent`，不在计算库里再写一套循环。`credit/auto_model_code/` 不进入执行链。

## 2. 不做什么

- 不优化「怎么批更多单」，不把放宽审批当成目标。
- 不建设毫秒级在线决策引擎，不从研究结论直接改生产策略或重训上线。
- 发现恶化后生成处置建议和一笔新的研究记录。没有负责人确认，不自动调额、不自动拒贷、不自动换模型。
- 切片贡献、结构效应和风险效应是证据。样本不够的切片不下结论。关联不写成唯一根因。
- 没有策略版本或决策日志时，不判断「策略失效」。没有用户提供的外部序列时，不判断「外部冲击」。这两种情况写成「现有数据无法区分」，并列出还缺什么。
- 只有放款表、没有拒绝客群表现时，不回放出「如果当时放宽会有多好」。
- 不恢复验收控制台，不把信贷页面放进 `/app`。
- 不把 `production_release_approved` 改成 true。
- 框架测试继续只用合成数据。信贷样本上的测试放在 `credit_risk_agent/`。

## 3. 存量资产监控与风险归因

### 3.1 用户要完成的事

1. 逐日盯存量组合的迁徙、逾期和风险异动。
2. 批量看出哪类客群、哪个渠道、哪一批进件在变差。
3. 自动做切片，生成风险报告，把变化拆开。
4. 在数据允许时回溯当时的策略，区分客群结构变化、组内风险变化，以及仍解释不了的部分。

### 3.2 数据

监控对象是已经形成的存量快照，不是审批进件流。

每次运行绑定一个时点快照，并和上一观察日或用户指定的基期比较。快照至少要能分辨：

| 用途 | 需要的字段 |
| --- | --- |
| 逾期与迁徙 | 借据或客户、观察日、逾期天数或阶段、坏标记 |
| 批次 | 放款月或进件批次、账龄 MOB |
| 定位恶化 | 维度登记表里的决策时点字段。渠道、客群、产品、地区只是默认项，见 3.5 |
| 策略回溯 | 决策当时冻结的策略版本，或当时的规则命中。没有则本项不做判断，见 3.6 |

本地表格和已配置的只读 DuckDB / ODPS 都可以作为快照来源。凭证只放在环境里。取数失败就停止，不用抽样结果代替全日组合。

### 3.3 每日运行

分析师指定组合、口径和观察频率，并明确打开每日运行。打开之后，新快照到达或到达约定观察日时，Agent 跑完同一套检查并留下报告。

没有这步确认，系统只保存监控方案，不自己定时跑。

每日报告固定包含：

- 和基期比，逾期率、迁徙率或滚动率变了多少，分子、分母和样本范围写在结果上。
- 恶化切片名单：维度、取值、本期水平、基期水平、差额、样本是否够。样本不够的只列入观察，不列入处置建议。
- 结构分解：组合变化拆成结构效应、组内风险效应和交互。三者之和应等于总变化。
- 策略对照：有策略版本时，按版本比较同一客群的表现，并写明版本差异。没有版本时，报告停在结构和组内风险，并写明无法判断策略失效或外部冲击。
- 处置入口：对样本足够且持续变差的切片，生成一条待人确认的处置研究。确认前不执行额度、准入或模型变更。

正常、没有越界的日子也留下「无新异常」的记录，不重复发同一条警报。

### 3.4 归因怎么下结论

| 能说的话 | 依据 | 不能说的话 |
| --- | --- | --- |
| 恶化主要来自客群结构变化 | 结构效应解释了总变化的主要部分 | 因此某一渠道的获客策略已经失败 |
| 同一客群内部风险变差 | 组内风险效应为主要部分，且样本足够 | 因此是宏观外部冲击 |
| 某渠道、某客群、某批次贡献了变化 | 下钻贡献和显著性通过样本门槛 | 这是唯一根因 |
| 某策略版本上线后，同一客群表现变差 | 快照里有版本，且版本前后客群可比 | 没有版本字段时仍写成策略失效 |
| 结构和策略版本都解释完后仍有缺口 | 残差仍大，或缺少外部序列 | 把残差直接命名为外部冲击 |

报告用这五类句子。用户可以追问某一个切片，Agent 只重算该切片和受影响的分解，旧报告保留。

### 3.5 切片在数据上怎么建

监控表是借据（或客户）乘观察日的明细，一行一个观察点。渠道汇总表不能再切，所以不能当唯一数据源。

字段分成两类，写入维度登记表后再参与定位：

| 类别 | 例子 | 取值冻结在 | 能否当作恶化来源 |
| --- | --- | --- | --- |
| 决策时点 | 渠道、产品、地区、客群标签、审批评分、金额、期限、策略版本、规则命中 | 放款或审批当时，之后不改 | 能 |
| 观察时点 | 观察日、MOB、逾期天数、逾期阶段、坏标记、余额 | 每个观察日重计 | 只做结果和成熟度，不做「原因维度」 |

登记表每一行还要有：来源列、取值类型（枚举、批次月、分档）、允许的最大取值个数、单元格最小样本。默认最大取值个数 30，最小样本沿用下钻的 50，且坏样本期望数至少 5。超过上限的原始列（门店、设备号、地址文本）先按登记的规则归并，归并不了就不进入自动定位。

评分、金额、期限如果要当切片，用分析师事先写好的分档，或沿用建模里已确认的分箱。Agent 不为了找出一个显著格子而临时改刀口。

批次比较必须对齐账龄。vintage 的分母只含已经走到该 MOB 的借据。新批次的早期逾期不和老批次的后期逾期直接比。

### 3.6 定位恶化怎么跑

一次监控先确认组合指标相对基期变差，再找来源。单维下钻对每个登记维度计算：切片本期比率、基期比率、差、样本占比、贡献（差乘本期占比）、两比例检验和样本是否够。结构分解把同一个维度上的总变化拆成结构效应、组内风险效应和交互。

一个切片要同时满足下面四条，才叫「定位到恶化客群」：

1. 基期和本期样本都够。
2. 比率变差的方向与组合一致，检验显著。
3. 贡献至少占组合总变化的 20%，或它是贡献最大的一格且坏账笔数增加达到分析师设的笔数门槛。
4. 该维度没有出现「每一格都在变好、组合却在变差」的结构反转。出现反转时，报告写结构变化，不把其中任何一格写成变差客群。

20% 和笔数门槛写在监控方案里，分析师可改。没改时用 20%。

常见维度都达不到这四条时，按这个顺序停，不继续穷举：

1. **普遍变差。** 组内风险效应大于结构效应，但没有任何一格同时样本够且显著。结论是整本变差，处置落在组合，不制造一个客群名字。
2. **结构分散。** 结构效应更大，或出现结构反转。列出份额变化最大的若干格，结论是客群构成变了，不把份额上升的那一格叫作风险根因。
3. **预登记的二维交叉。** 只跑登记表里点名的配对，例如渠道×放款月、渠道×策略版本、评分档×渠道。格子仍要过同一套样本和贡献门槛。不跑全部两两组合。
4. **预登记连续字段的探索性分档。** 对评分、金额、期限按已有分箱看一维贡献。报告标题写「探索性分档」，分档规则要分析师确认后才能变成正式维度。
5. **现有维度无法定位单一客群。** 写明试过哪些维度和配对、组合变化还剩多少没被最大的那一格解释。处置项是「补充维度」或「按整本处理」。不扫描全部未登记列，也不用决策树临时找一群人。

### 3.7 策略回溯怎么跑

策略版本和规则命中如果已经写在决策记录上，回溯就用这些列，取值是决策当时的记录。监控日之后的新策略不回写旧借据。本产品不另建规则目录，也不靠目录补版本号或补规则正文。绩效表不反推当时改了哪一句。

回溯只在账龄对齐的同一批放款里做：

1. 用策略版本做结构分解。结构效应大，表示更多余额进了另一个版本覆盖的人群。组内风险效应大，表示同一个版本覆盖的人变差了。
2. 版本内部再按渠道和决策评分档看结构。版本内构成变了，结论是「这个版本新吸进来的客群变了」。构成稳定而比率上升，结论是「同一版本、同类客群的表现变差」。
3. 有规则命中时，在同一批次、同一渠道、已放款的借据里比较命中与未命中的坏账率。这是已放款账本上的差异。被拒申请人没有表现时，不把这个差异写成放宽或收紧后的真实坏账。
4. 同一比较窗口里出现多个版本号时，按版本拆开，不把整窗写成某一版失效。决策记录上看不出某一版中途改过正文，报告不写「版本在窗口内变更」。
5. 没有版本、没有命中，这一节固定写「无法判断策略」。有版本但账龄对不齐或样本不够，写「有版本，但这次样本不能比」。

「策略失效」只在第 2 步后半句成立时使用，并且同一句里写上版本号、批次、MOB 和样本数。外部冲击仍只在分析师提供了外部序列、并且结构和版本都解释完后仍有缺口时单独作为未知项，不从残差自动命名。

### 3.8 历史策略不在本产品维护

线上规则只留在决策引擎。本产品不导入规则包，不登记旧版本正文，不核对生效区间，也不把引擎规则抄成一份离线副本。`mine_rules` 只在已放款样本上找高提升度的单变量切分，可以当作探索，不能当成当时的生产策略。

实绩回溯只用决策记录上已经有的列：

- 有策略版本号：按版本做 3.9 的结构分解。带版本号的放款低于分析师设的覆盖门槛（默认 90%）时，写「版本覆盖不足，无法判断策略」。
- 有规则命中标记：在版本内部再比较命中与未命中。没有这列，就停在版本，不解释「改了哪条规则」。
- 两列都没有：策略一节固定写「无法判断策略」。不要求分析师补录。

版本号和命中标记都是引擎落库时写下的，本产品只读。读不到就不做策略判断，不另建绑定表去补。

### 3.9 回溯功能怎么做

回溯是监控运行中的一步，读当次快照和决策记录上已有的版本号、命中标记，写出策略一节。它不重新执行决策引擎，也不用今天的规则去跑历史申请，也不读取一份规则目录。

步骤：

1. 决策记录上没有版本号，整节停，输出「无法判断策略」。
2. 取本观察日已成熟到指定 MOB 的借据，以及基期同样 MOB 的借据。账龄对不齐就停，输出「有版本，但这次样本不能比」。
3. 版本号直接取自决策记录。没有版本号的笔数单独列出。覆盖率不够就停，输出「无法判断策略」。
4. 在这批对齐后的借据上，用版本号做结构分解，得到结构效应和组内风险效应。
5. 组内风险效应更大的那个版本，再按渠道和决策时评分档做一次结构分解。构成变了，结论停在「新吸进来的客群变了」。构成稳定且样本够，才写「同一版本、同类客群的表现变差」，并附版本号、批次、MOB、样本数、分子和分母。
6. 仅当决策记录上有规则命中标记时，对第 5 步留下的渠道，在已放款借据里逐条规则比较命中与未命中。样本不够的规则只列入观察。被拒申请人没有表现时，不把命中差写成收紧或放宽后的坏账。没有命中标记，不解释改了哪条规则。
7. 报告引用决策记录上的版本号和快照号。之后新落库的版本不改已经发出的这节文字。

同一张决策记录上若有多族版本号（准入、额度、定价），分析师可以指定只看一族。没指定时分族各跑一遍，不把不同族的版本混在同一次分解里。

### 3.10 新规则的历史命中怎么回放

3.7 到 3.9 用的是已经发生的命中，用来解释当时那一版策略。历史命中表里没有新规则的列。只有新规则是若干条已经记录过命中的旧规则的并且、或者、取反时，才能单靠旧命中表计算。新阈值、新顺序或新变量都要重新执行规则。执行所用的取值，是决策当时引擎已经算完并写入日志的变量向量，不是本产品现算的字段。向量里没有的变量，该笔决策对这条规则记为无法回放。日志只有放款、没有被拒申请时，回放范围就是已放款账本。

当前现状是：策略规则部署在决策引擎上，本产品打不通这套引擎；决策特征和数据分析用的特征已经落库，可以直接取。新规则会不会命中，必须有一处把规则套到这些特征值上。打不通引擎时，这一处就是本产品里的离线规则运行时。它是一段随实验调用的计算，不是一份要人日常维护的规则库或特征库。

特征不在本产品维护。回放直接读该次快照里已有的列，不建特征字典，不登记字段口径，不和引擎的变量清单对账。句子里点到的列不在这批数据中，该条候选失败并写明缺哪一列。同一列在不同时期含义不同、且快照里已经有区分列时，报告按该列拆开；没有区分列，就整批使用快照里的这一列，不另做口径台账。

规则也不在本产品长期保存成目录。分析师用一句话描述要试的条件，Agent 在当次快照的列上生成若干阈值或切片，放进这一次回放。规则正文存在这次实验的记录里，用来重读这份报告，不用来跟上线规则对齐。下一次实验从新的一句话开始。线上规则变更后，不需要回来改这些记录。

这套运行时只包含四件事：比较、并且、或者、取反，加上规则顺序、首条命中或全部命中、缺失值政策。取值只用已经落库的特征，不在这里计算新变量，不调用外部数据，不审批真实申请。引擎内部函数无法在这里执行，该条候选失败。因此它和线上决策引擎是两套执行，结果不必逐条相同；回测结论只代表这一次实验的规则在该快照上的命中。

若决策记录上还有当时的策略版本或规则命中，3.9 的实绩回溯一并可用。没有这些列时，实绩回溯写「无法判断策略」；新规则的回放不受影响。

批量回测的步骤：

1. 分析师给出人群和要试的条件。Agent 生成多版候选，全部属于这一次实验。引用了快照里没有的列、或不支持的运算时，该候选失败。
2. 回放读取这一批历史决策及其已落库特征。
3. 离线规则运行时对每笔决策、每个候选计算命中和动作，写入这一次实验的回放命中表。不回写决策引擎，也不改库里的原始特征。
4. 对比表给出每个候选的命中人数；若库里有当时的通过或拒绝结果，再给出实际通过但候选会拒绝、实际拒绝但候选会通过、两边动作相同。分母是本批能取到所需特征的决策数。
5. 坏账只统计该候选会通过、且已经放款并成熟的借据。历史上被拒绝、该候选会通过的申请，坏账记为未知。
6. 人选定某一版之后，上线仍在决策引擎里由人部署。本产品给出这一版的规则正文和回测结果，不调用引擎发布，也不把这一版登记成新的线上规则。

## 4. 风控建模与回测自动化

### 4.1 用户要完成的事

收缩期的重复劳动交给 Agent：分箱、KS、PSI、特征筛选、训练或评估、阈值回测、对比报告、版本记录、稳定性跟踪。分析师负责定标签、定约束和决定哪一版留下。

人力价值用「同一位分析师完成一轮对比所需的手工步骤」来衡量。不把回测提升写成已经减少的坏账。

### 4.2 一次实验

1. 课题绑定快照，写明用途、预测时点和标签。
2. 标签是多值时，先指定好、坏、灰和无效。灰样本怎么处理没写清，实验不开始。
3. 已有评分只做评估和稳定性时，不自动训练新模型。
4. 用户要求新候选时，Agent 跑样本画像、分箱与 IV、特征筛选、训练、KS/AUC、PSI，并留下和上一版或指定基线的对比表。
5. 回测是在这份历史快照上比较候选评分、分箱或阈值，对照已确认的坏标记和通过约束。结果标明历史观察范围。拒绝样本没有表现时，放宽后的坏账保持未知。
6. 每一版记下数据快照、标签映射、特征、参数、指标和文件。后一版不覆盖前一版。
7. 稳定性用后续快照上的 PSI 和排序指标跟踪。变差时打开一条监控侧能看见的稳定性记录，仍由人决定是否重训。

训练默认用现有逻辑回归和 WOE。LightGBM 只在环境里有依赖且用户点名时使用。评分卡和模型包沿用现有产物，页面提供下载，不提供生产发布。

### 4.3 对比报告

同一课题里并排看基线和候选：

- 样本、标签映射、特征数、剔除掉的列
- KS、AUC、PSI、分箱稳定性
- 在用户给出的通过率或坏账约束下，阈值或额度方案的历史表现
- 哪一版更好、哪一项未知、分析师还要拍板什么

报告是实验资产的一种看法。实验版本和模型文件仍单独保存。

## 5. 信息架构

```text
组合或信贷产品
  数据快照（按观察日）
  已确认口径
  监控方案（未开启 / 每日运行中）
    每日风险报告
    待确认的处置研究
  建模课题
    实验版本
    对比报告
    稳定性记录
```

分析师打开产品后看到两列工作，而不是一串框架能力：

| 区域 | 监控 | 建模回测 |
| --- | --- | --- |
| 左 | 组合、观察日、是否已开启每日运行 | 课题和实验版本 |
| 中 | 今日是否恶化、切片、分解、缺的证据 | 实验步骤、对比、待拍板项 |
| 右 | 口径、策略版本有无、报告历史 | 标签映射、特征、产物文件 |
| 底 | 追问某个切片；确认或搁置处置研究 | 改约束后只重算受影响的候选 |

进展来自实际计算：在取快照、在等口径、在算迁徙、在等标签、已生成报告、计算失败。不用进度条百分比。

## 6. 功能需求

### 6.1 共用

- 一个租户只能看见自己的组合、快照、报告和实验。
- 列角色以人工确认为准。自动识别只做建议。改口径后旧结果保留。
- 比率和迁徙结果带分子、分母、时间和样本范围。
- 失败时留下原因和当时的口径，修正后可以重跑。
- 运行中可以停止。未完成的计算不显示为成功。

### 6.2 监控

- 可以保存监控方案：组合、基期、切片维度、逾期或迁徙指标、样本门槛。
- 可以打开或关闭每日运行。关闭后不再生成新的定时报告，历史报告还在。
- 每次运行生成第 3.3 节的报告，并引用本次快照和口径版本。
- 样本足够且相对基期变差的切片进入处置研究列表，状态是待确认。
- 无策略版本时，报告中的策略结论固定为「无法判断」。

### 6.3 建模与回测

- 未完成标签角色时不能训练、不能评估。
- 一次实验产生可追溯版本，内容见第 4.2 节。
- 对比报告能同时打开基线和至少一个候选。
- 后续快照可以挂到已有版本上做 PSI 和排序稳定性。
- 回测约束由用户给出。没有约束时只出排序和稳定性，不编造一个最优通过率。

## 7. 验收

用一份可复核的存量样本和一份建模样本，各走通一次。

监控：

1. 两个观察日的快照能算出迁徙或逾期变化，并拆成结构效应和组内风险效应。
2. 至少一个渠道、客群或批次被标成变差或样本不足。
3. 拿掉策略版本字段后，报告写明无法判断策略失效或外部冲击，且不出现这两种结论。
4. 每日运行在用户打开后才会再次出报告；关闭后不再出新报告。

建模：

1. 标签未确认时训练不启动。
2. 确认后得到一版实验，报告里有 KS 或 AUC、PSI 或分箱结果，以及和基线的差异。
3. 再跑一版不覆盖前一版。
4. 在历史快照上的阈值或评分对比标明观察范围；缺少拒绝样本表现时，放宽后的坏账是未知。

业务页面不出现 `/app` 演示，也不出现验收控制台。开发计划里的平台验收门和试点门不因本文改成已完成。

## 8. 确认后才实现

| 新增 | 落点 |
| --- | --- |
| 监控 Agent、建模回测 Agent | `credit_risk_agent/` 下的新包，各用一个 `AgentProfile` |
| 业务前端 | 新建应用，两个工作台 |
| 快照、监控方案、实验版本 | 业务自己的记录，不写入 `agent_platform` 的表 |

## 9. 请确认

回复「确认这份需求」即同意下面四条。要改的话指出哪一条。

1. 一级产品就是存量监控归因，以及建模回测自动化。目标是早发现恶化和减少重复实验，不是多批单。
2. 两个 Agent 共用数据，业务前端新建，不改 `/app`。
3. 没有策略版本就不判断策略失效；没有外部序列就不判断外部冲击。每日监控必须由分析师打开。
4. 回测和收益都停留在历史观察或假设。研究结论不能变成生产变更。
