# Credit Agent 产品设计 V3：开源底座上的信贷研究与验证工作台

日期：2026-10-29。状态：完整目标设计，新增功能待开发。技术选型见 [开源框架决策](OPEN_SOURCE_AGENT_FRAMEWORK_SELECTION.md)，交付安排见 [开发计划](CREDIT_AGENT_DEVELOPMENT_PLAN_V3.md)。

## 1. 产品目标与交付结构

产品定位：帮助信贷风控团队把业务问题转化为可执行研究，自动完成分析、策略比较、模型实验和监控诊断，交付可复核、可接续验证的成果。

交付拆成两个有独立验收的产品：

1. **Agent Platform 1.0**：对开发与运维开放的稳定执行底座。复用 Deep Agents/LangGraph，提供身份、工具/Skill、上下文、子 Agent、代码/浏览器、任务恢复、评测与运维。
2. **Credit Studio 1.0**：在同一底座上的信贷领域应用。提供数据口径、策略/模型资产、研究对话、专业比较视图、实验与监控反馈。

平台验收先完成，再进入产品适配主阶段。平台验证使用通用表格分析、代码执行、受控网页和模拟长作业；不先开发大批信贷页面来掩盖底座问题。

## 2. 目标客户、角色与价值

优先试点：有现成信贷数据与策略系统、有稳定研究需求、能提供业务负责人复核的团队。此为客户假设，实际付费和接入成本需要试点验证。

| 角色 | 核心任务 | 主要交付 |
|---|---|---|
| 策略/风控分析师 | 诊断变化、评估规则、比较方案 | 证据充分的策略研究与变更包 |
| 模型开发/验证人员 | 挑战已有评分、训练候选、复核适用性 | 实验记录、模型包和验证材料 |
| 产品经理 | 明确业务目标、约束与测算假设 | 规模/风险/收益权衡、待验证条件 |
| 风控/策略负责人 | 选定方案和验证计划 | 候选比较、风险边界及复核依据 |
| 平台管理员/运维 | 管理模型、资源、权限和发布 | 可用性、审计、成本和能力版本 |

效率价值先用包含人工复核的总工时验证；质量用口径/计算/方法错误与返工验证；经营收益需要后续成熟表现和合理对照验证，不能从历史回测直接承诺。

## 3. 平台产品：先完成的通用能力

### 3.1 开发者接口

提供 `AgentProfile` 声明：模型配置、模式、工具版本、Skill、子任务模板、数据/执行范围、预算、checkpoint/store namespace、验收器和 telemetry。开发者通过配置和 adapter 接入新场景，不复制 runtime。

Profile 是服务端发布资产。用户输入不能任意替换 system policy、加载未审批插件或提升权限。开发环境与生产环境的配置、密钥和数据分离。

### 3.2 平台控制台

| 区域 | 功能 | 验收关注 |
|---|---|---|
| 运行与会话 | 发起通用任务、事件流、暂停/取消/恢复、必要确认 | 重启/断线后的真实状态 |
| Agent 配置 | 模型、模式、工具/Skill、子任务、预算 | 固定版本、变更预览、模板复用 |
| 工具与连接 | 查找、测试、启停、MCP、资源 scope | 发现和调用权限分离 |
| 环境 | sandbox、browser、资源配额和运行镜像 | 实际隔离、状态与回收 |
| 轨迹与质量 | 模型/工具/子任务/Code Mode trace、eval | 正确关联、去敏、失败复现 |
| 版本与发布 | 能力包、候选改进、测试、发布、撤销 | 活动任务不热替换行为 |

首版控制台重在调试和管理，不要求复制 Codex IDE、文件编辑器或通用办公套件。通用文件阅读与执行视图优先使用框架能力和现有组件。

### 3.3 平台使用契约

Plan 生成方法与执行建议；Execute 在授权内自主推进；Review 读取成果并复核。滚动规划与局部 ReAct 配合。技术操作无需用户逐步批准，业务事实缺口、已确认口径变化和新增敏感效果才出现必要交互。

所有运行给出：当前目标、实际动作、已产生证据、正在等待什么、消耗和下一步可恢复位置。框架的模型内部推理不直接进入业务 UI，流事件经白名单转换为行动说明。

## 4. 信贷产品的信息架构

以“机构 → 信贷产品 → 持续业务资产 → 研究课题 → 实验/变更”为主线。聊天属于课题的交互记录，不能成为策略和模型资产的唯一容器。

导航包含：产品概览、研究课题、数据与口径、策略资产、模型与实验、监控、知识与方法。管理员另有平台入口，普通分析师不必操作底层插件或编排图。

| 资产 | 必需内容 |
|---|---|
| 信贷产品 | 负责人、客群、渠道、目标、约束、基线策略/模型版本 |
| 数据集 | 来源、快照、单位、时点、字段语义、可访问范围和质量 |
| 指标/标签 | 分子分母、窗口、成熟性、排除/灰样本、来源和版本 |
| 策略版本 | 规则、顺序、首命中/全命中、阈值、缺失处理、适用范围 |
| 模型版本 | 特征、切分、训练环境、性能、适用性、产物和验证状态 |
| 实验 | 基线、候选、目标、数据、选择规则、验证使用记录和结果 |
| 变更包 | 方案差异、证据、测试、审批衔接、监控和回滚建议 |
| 监控计划 | 指标、归属版本、预警条件、运行频率、负责人和处理记录 |

## 5. 四类完整工作包

### 5.1 分析与诊断

输入：业务问题、产品、样本与比较期。Agent 检查质量和可比性，分析趋势、结构与组内变化，开展有依据的下钻。

交付：指标定义、真实图表、贡献分解、相关因素、替代解释、局限和后续验证建议。关联不标为根因；不足成熟窗口不硬算同口径效果。

验收：分析单位、样本和分母可对账；当前问题得到回答；失败或不可比不被报告文案掩盖。

### 5.2 策略研究与比较：首要差异化场景

输入：现行策略、决策日志、相关字段快照、表现数据、目标和约束。支持规则导入与执行语义确认，不能只上传一张放款表就宣称全量策略回放。

Agent 完成：基线复现 → 规则命中/重叠/冲突与增量贡献 → 候选调整 → 同口径回放 → 稳定性/独立验证 → 权衡与方案说明。此为用户可理解的研究主线，内部不固定每一步必须执行。

策略比较表至少显示：方案版本、规则差异、覆盖、全量申请通过率或明确范围内保留率、风险定义、规模、假设收益、约束满足、验证状态和未知项。

风险和收益分别标明 `历史观察 / 模型估计 / 假设测算 / 实验验证`。缺少拒绝客群标签时不填造放宽策略的真实坏账率。无可行解则交付冲突约束与可调整范围。

交付：基线/候选比较、增量贡献、独立验证记录、参数来源、敏感性分析、规则配置/测试文件和小流量实验建议。首版衔接现有决策引擎的导出包，不建设新的毫秒级在线决策引擎。

### 5.3 模型研究与挑战

输入：业务用途、预测时点、标签、样本和可用特征。已有评分评估不强制训练新模型；只有研究目标需要时才发起候选模型实验。

Agent 检查特征时点、实体/时间隔离、成熟性和最终验证使用记录；执行筛选、基线与候选、必要调参和验证。算法优先复用当前 LR、WOE、LightGBM 等计算库，按需要扩展。

比较不仅包含 AUC/KS，还包含固定业务约束下的决策表现、稳定性、校准、可实现性和限制。最终 OOT 反馈参与开发后，不再称未见验证。

交付：模型卡、实验清单、固定代码/环境、模型文件、评分脚本、独立评估和使用边界。研究交付与生产部署授权分别记录。

### 5.4 监控与持续研究

Agent 根据被接受的研究形成监控草案：指标、周期、数据依赖、阈值来源、基线、负责人和触发行为。用户或有效组织授权激活后，由成熟调度组件执行；没有授权的草案不自行变成定时运行。

监控先检查数据新鲜度/质量，再区分客群结构、策略版本和模型表现变化。异常生成关联原版本的新研究课题，复用证据并提出调查。通知由明确配置决定，正常不变不反复打扰。

交付：异常卡、影响范围、证据、待确认条件和处理记录。自动发现异常不等同自动改策略或重训上线。

## 6. 核心交互与专业视图

### 6.1 新建研究

用户选择产品/已有资产，输入问题并绑定数据。系统沿用已确认定义，Agent 先执行必要检查。缺少必需事实时展示一个有上下文的问题，允许选项和自由回答；不让用户选择内部算法节点。

### 6.2 任务工作区

```text
左侧：产品 / 研究课题 / 搜索与历史
中央：目标、Agent 工作记录、必要问题、阶段成果、继续追问
右侧：成果 / 数据与口径 / 策略或模型 / 实验 / 证据
底部：补充要求、附件；暂停/取消/恢复与状态清楚区分
```

进展来自实际动作：查询进行中、等待训练、缺少定义、复核未通过等，不用预设阶段条或虚假完成百分比。长期计算可离开页面，回来后重建同一投影。

### 6.3 专家检查与变更

专家可查看指标来源、分箱、规则增量、样本切分、脚本和版本；可提出调整并重算。修改已确认口径时，显示差异、受影响成果与重算范围，旧结果保留。

基线/候选比较使用结构化表和曲线，允许按客群/渠道展开。报告只是成果的一种呈现，不替代实验、模型和策略资产。

### 6.4 接受研究与实施衔接

研究交付后可以接受、要求补充、驳回并说明原因。接受研究表示材料可用；进入外部实施时生成独立变更请求。发布和回滚衔接已有系统权限流程，不能从“用户认可报告”推导生产批准。

## 7. 用户旅程示例

“最近审批通过率下降，在不恶化已定义风险指标的条件下比较调整方案。”

1. 引用产品当前策略、历史申请日志和已确认风险定义。
2. Agent 核对策略基线，发现某规则增量覆盖变化；图表解释渠道结构与组内变化。
3. 形成多个有来源的候选，回放并展示可识别范围，缺少标签部分保持未知。
4. 用户补充新客规模要求，系统将其加入同一目标，并仅重算受影响候选。
5. 候选冻结后使用独立验证，交付权衡、证据和实验建议。
6. 负责人接受研究，生成供现有决策系统使用的变更包。
7. 授权实施后回收策略版本与后续表现，按预设监控触发下一轮研究。

同一旅程中的分析、建模和测算按目标需要调用；不分别要求用户跨多个工具重复输入口径。

## 8. 数据、权限和知识设计

文件和只读数仓接入形成快照与血缘；大数据通过查询下推/分块执行，Agent 不静默抽样替代原目标。业务库、标签、策略、模型和产物分别授权，机构隔离贯穿缓存、checkpoint、工具和下载。

知识分为行业方法、机构制度、产品口径、历史案例；标明来源、适用范围、时间和状态。经验检索只能提出方法建议，不能覆盖已确认事实。失败案例用于受限评测，不作为成功业务经验推荐。

模型出域与日志保留由机构配置。用户页面显示必要的数据缺口和估计性质，内部架构术语只出现在开发/管理视图。

## 9. 质量、指标和商业验证

| 维度 | 核心指标 |
|---|---|
| 使用 | 重复使用的真实课题数、产品/团队覆盖、持续资产引用 |
| 效率 | 总交付时间、包含复核的人工工时、必要追问次数 |
| 可信度 | 口径/计算错误、越界结论、证据缺失、返工率 |
| 业务采用 | 被验收并进入后续验证/实施的有效变更数 |
| 运行 | 恢复成功、重复副作用、权限违规、资源/模型费用 |
| 商业 | 付费试点、续用意愿、客户接入工时、可复用程度 |

首批付费试点固定一个产品、一类研究与一组验收要求。建议软件许可/订阅与部署集成分开计费，定价在真实预算和交付成本访谈后确定。本设计不虚构市场报价或经营收益。

## 10. 版本边界和当前资产复用

目标 1.0 包含通用平台验收、分析诊断、存量策略比较、候选模型研究和授权监控闭环。生产实时决策引擎、复杂资本模型、全自动策略发布、全面 native desktop 和自动训练基础模型属于后续独立范围，不能混入本期“框架完整”的定义。

当前 `analytics/`、`modeling/`、数据快照、口径版本、知识正文和已有报告能力继续复用并做专业回归。旧自定义 loop、局部代码生成循环、整体状态调度和 API 线程池逐步迁出主执行路径；历史课题、审计和产物保留。

现有五项 Skill 转为框架支持的发布包，先审核适用条件、操作契约与权限，不直接让模型读取未经发布的全目录。产品前端复用现有 React 技术栈，随着新 API 逐页适配。
