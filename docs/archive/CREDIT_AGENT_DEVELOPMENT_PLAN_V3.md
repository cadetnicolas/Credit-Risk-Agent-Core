## 1. 总体安排与人力假设

两个里程碑：**Gate F：Agent Platform 1.0 框架底座验收**；**Gate P：Credit Studio 1.0 产品试点验收**。Gate F 前，重点完成通用平台集成和可观察的验收任务，产品侧可以做业务访谈与数据契约准备，正式功能适配集中在 Gate F 后。

建议团队：2 名 Agent/后端工程师、1 名执行平台工程师、1 名全栈工程师、1 名数据/模型工程师、1 名 QA；另需约半职 SRE、产品经理和信贷专家参与。允许一人兼任，但关键验收需要独立复核。

在上述人员、可用测试模型、可部署 PostgreSQL/RabbitMQ/sandbox、试点数据及时提供的假设下，基线约 **21 周，加 3 周缓冲，按 20–24 周规划**。这不是已测量的交付承诺。前两周基于 PoC 和部署条件重估；人力显著减少时应缩范围或延长时间，不能按同一时间承诺。

## 2. S0：一周选型验证，避免早期锁错底座

### 2.1 工作

以 Deep Agents `0.7.32` 和 AgentScope `2.0.11` 为本次调研基线，在独立环境使用相同工具与数据跑最小对照。先验证真实结构化工具调用与模型兼容，再验证恢复和安全组合；不使用聊天演示评价生产能力。

Pydantic AI Harness 保留为切换路线，不同时做三个完整 PoC。没有硬阻断时，按推荐继续 Deep Agents，不无限延长框架比较。

### 2.2 用例与交付

| 用例 | 要证明的能力 |
|---|---|
| 通用 CSV 检查与图表 | 工具、代码、文件后端、结果引用 |
| 多轮研究并两次压缩 | 原目标、事实和引用保持有效 |
| 进程中断后接续 | checkpoint 可恢复，副作用可核查 |
| 两个子任务与取消 | 权限子集、预算、结果和取消传播 |
| Code Mode 内层工具 | 绕过外层 HITL 时工具自身仍鉴权 |
| MCP 与工具版本变化 | 发现、schema、执行权分离 |
| 私有模型/选定 API 模型 | 能力协商与失败状态明确 |
| SSE 断线与补充要求 | 事件可补读，消息不丢、不只取最后一条 |

交付：独立 PoC 目录、运行记录、失败原因、锁定候选依赖、ADR、必须补齐的差距与成本。记录 passed/failed/pending，不把未测算成支持。

否决条件：必须长期 fork loop/checkpointer 才能满足硬要求、工具入口无法落实授权、关键恢复组合不可复核、机构模型无法可靠结构化调用。只因某一框架组件不直接提供 SSO 不构成否决，可以接入成熟身份系统。

## 3. F1–F4：平台开发工作包

| ID | 工作包 | 复用/增量与交付 | 验收与依赖 |
|---|---|---|---|
| F-01 | 依赖和代码结构 | 单仓 runtime adapter，固定 SDK/扩展/镜像，SBOM | S0；同一逻辑任务只有一个执行 owner |
| F-02 | 身份与数据 scope | 接机构 IdP/测试 Keycloak，资源授权和受限工具 wrapper | 伪造 Host/租户/账户不能越权 |
| F-03 | Harness 集成 | 使用 `create_deep_agent`、模型 adapter、模式配置和流事件 | 原生工具与兼容错误可验证，不重写循环 |
| F-04 | 持久状态 | 官方 Postgres saver/store，应用 case/run/message 映射 | 重启、版本固定和单 thread 写租约 |
| F-05 | 任务投递 | Celery/RabbitMQ，outbox 发布和去重消费 | DB 提交与 broker 投递之间失败可恢复 |
| F-06 | 执行环境 | OpenSandbox/现有平台 adapter，隔离文件、网络和资源 | 真实进程/文件/网络隔离测试 |
| F-07 | 作业效果账本 | job/attempt、外部句柄、输入指纹和核查 | 崩溃、未知提交、迟到结果与取消竞争 |
| F-08 | 上下文和记忆 | 复用压缩/卸载/Skill，增加事实和权限投影 | 压缩后目标/活动作业/事实与引用完整 |
| F-09 | 工具平台 | 官方工具/MCP 协议，发布目录和按需发现 | 同名换版、schema 漂移、不可用状态明确 |
| F-10 | Code Mode | 官方 QuickJS，受限 PTC，初期禁用其直接 task 委派 | 内层权限/费用/限额可追溯；不暴露敏感写工具 |
| F-11 | 子 Agent | 复用框架委派，声明式角色与权限交集 | 深度/数量/费用限制和独立证据结果 |
| F-12 | 持久子任务控制 | 明确普通 subagent 与跨 Run task receipt 的范围 | 内置 async adapter 部署/许可满足才用；否则复用队列+子 graph，不重写子 Agent loop |
| F-13 | Browser 工具 | Playwright 专用 context/环境、origin 和接管 adapter | 测试门户完成 observe/act/verify，未知提交不盲点 |
| F-14 | Telemetry/控制台 | 官方 callbacks 接 OTel，运行/工具/子任务/cell 轨迹 | 同一任务可串联定位，日志脱敏、成本 unknown 可对账 |
| F-15 | 测试与发布 | 合成基准、故障、安全、耐久、版本灰度和撤销 | 通过 Gate F，备份恢复演练有实际记录 |
| F-16 | RSI 基础 | 主框架执行候选修改、现成测试、独立发布环境 | 一个通用失败案例形成受测版本后代；拒绝劣化候选 |

F-12 是明确差距：Deep Agents 普通同步子任务和远程 async subagent 不自动等于本产品全部邮箱/接管协议。先确定需要持久控制的场景；以框架 graph 做子执行单位和成熟队列做投递，薄应用层只管理 task contract/receipt 和控制事件。

RSI 在此阶段只验收基础设施：候选补丁、离线对照、谱系和发布隔离。信贷方法改进在产品阶段加入真实领域评测，不能用一个合成任务宣称信贷能力持续提高。

## 4. Gate F：什么叫“框架开发完整”

必须满足全部上线范围能力，不以“可以问答”或功能数量验收：

1. 单 Agent、滚动计划/局部 ReAct、Plan/Execute/Review、工具发现与 Skill 可用。
2. 通用任务能持续执行、阶段性交付、接受补充，并正确等待计算/人工。
3. 至少两个隔离子任务可委派/观察/取消，持久子任务恢复路径清楚。
4. Code Mode 工具组合、真实 Python/SQL sandbox 和受控 browser 工具均跑通安全用例。
5. SSO、资源权限、批准、凭据、租户与数据 scope 真实生效。
6. checkpoint、outbox、队列、外部账本在崩溃窗口保持一致，不重复产生有效提交。
7. 轨迹、费用、用户状态、告警、发布和撤销可操作。
8. 通用 RSI 候选闭环与评测隔离成立；预算与授权不能自改。
9. 开发者接入新工具/Skill/子任务模板，无需修改上游 loop。
10. 有依赖 lock、容器 digest、配置模板、部署手册、测试记录和已知限制。

验收引用 [P01–P15](AGENT_PLATFORM_QUALITY_OPERATIONS.md)、[R01–R15/L01–L08](AGENT_ARCHITECTURE_V2_ROADMAP.md)。数值目标：安全/确定性/恢复关键用例全部通过；初始通用 Agent 基准建议至少 30 个任务、每项 3 次，完成率目标 ≥90%，并报告失败分布与不确定性。这是建议门槛，正式冻结前由评测负责人确定任务范围与预算。

至少包含 100 个动作、3 次压缩、2 次进程重启的耐久案例；低级副作用必须幂等。模型连续输出正确不是恢复测试的替代。

Native desktop、所有供应商模型、所有异步子任务部署方式无需本期全支持；但平台必须有能力声明、adapter 接口和明确 unavailable。Browser 是本期 Computer Use 的实际验收范围。

## 6. Gate P：产品试点验收

试点先限定一个产品、一个主场景、一个可复核基线。至少覆盖：正常研究、多轮补充、口径变更、无可行策略、标签不足、模型独立验证、异常诊断、运行中断恢复。

验收包含：

- 业务口径和计算由指定专家复核，关键指标有可重算依据。
- 策略基线在约定容差内复现，候选比较不越出样本可识别范围。
- 交付被负责人接受，并至少进入正式评审/后续验证；不能强迫客户为完成验收而上线。
- 与原方式比较包含人工复核的总工时、返工和费用，不只比较生成报告速度。
- 数据权限、日志去敏和机构部署要求通过；真实故障演练可恢复。
- 风险表现未成熟时，仅验收效率、质量和采用，经营收益继续追踪。

具体节省百分比和商业收费在试点前约定，不在缺少客户基线时预写成事实。

## 7. 迁移与代码组织

下面是当时建议的薄集成层，没有按这个树落地。计算库现在在 `credit_risk_agent/src/credit_agent/`。可复用的 Agent 运行时是仓库里的 `agent_platform/`，不要在计算库里再复制一套。

```text
src/credit_agent/
  platform/                 # 官方框架配置与适配，不复制其核心
    agent_factory.py
    profiles.py
    model_adapters.py
    tool_wrappers.py
    checkpoint_config.py
    event_bridge.py
    subtask_adapter.py
  execution/                # 成熟队列/sandbox/browser 接入与效果账本
  identity/                 # IdP、scope、grant 与凭据适配
  research/                 # 目标、事实、证据、实验与验收
  credit_risk_agent/       # 领域计算、Skill 与 MCP 项目
  analytics/ modeling/ data/ # 继续复用的计算库
```

依赖升级先在独立 runtime 包/环境验证。过渡期旧引擎和新框架可分进程部署，按 Run 的 runtime_version 路由，避免在同一解释器中强行混合不兼容依赖。

保留旧 API 的读投影和历史课题；新任务逐步切换。既有 checkpoint 不直接灌入新框架，转换明确的目标、事实、证据和产物，历史轨迹保持 legacy 标记。迁移前备份，绝不清空真实课题或审计。

旧 `agent/runtime.py`、旧图的研究调度和 API 线程池在新任务验收后退出主路径；已有统计库保留。旧沙箱内部模型修复循环迁由主框架管理，避免一项工具偷偷启动第二套不可见 Agent 循环。

## 8. 依赖、部署和运行成本

计划基线：Python SDK、PostgreSQL、Celery/RabbitMQ、OpenSandbox 或已有计算平台、对象存储、机构 IdP、OTel collector 和现有监控后端。开发使用容器化本地依赖，生产按机构要求部署；无需为了框架验收先引入 Kubernetes。

不强制购买 Managed Deep Agents、LangSmith Deployment、LangSmith 或其他商业控制面。使用商业服务时单独确认数据流、部署和许可；不能把商业能力计入开源 SDK 验收。

私有部署默认关闭未授权的外部 tracing/telemetry 与自动公共 Skill 加载。通过出站网络观察确认数据流向，不能仅凭应用配置写着“私有化”就通过验收。

任务调度优先使用客户已有调度或成熟周期任务组件，不新造 cron 系统。sandbox、worker、browser 和 eval 分资源池；按模型与计算成本分别核算预算。

SBOM/镜像来源、依赖锁定、许可证和网络出域在 F 阶段完成。预算分为研发投入、测试模型调用、计算/存储、身份/运维及客户接入；缺少人力单价和试点规模时不虚构总费用。

## 9. 主要风险与处理

| 风险 | 处理与停止条件 |
|---|---|
| beta Code Mode/API 变化 | pin 版本和兼容测试，功能 flag，PTC 只开放安全集合 |
| 模型宣称兼容但工具能力不足 | S0 真实多轮/并发/错误验证；不足时调整模型或框架，不能靠提示词硬撑 |
| checkpoint 被误当副作用保证 | 外部账本+幂等+核查；不明结果暂停重试 |
| 中间件权限遗漏 | 工具自身统一校验；测试直接/PTC/子 Agent/MCP 全入口 |
| 多租户敏感数据进入上下文/缓存 | namespace、读取授权、摘要与原产物分类；撤权后验证缓存失效 |
| 数据接入拖延 | 平台通用验收独立推进；产品试点在数据契约满足后开始 |
| 框架集成演变成长期 fork | ADR 限制 public API；无法薄适配时触发选型复核 |
| 领域范围膨胀 | 首期固定存量策略研究闭环；后续复杂任务独立排期 |
| RSI 评测过拟合 | 隐藏基准、独立预算、有限搜索、未证实不发布 |

## 10. 下一步可执行起点

按 S0 建立隔离 PoC 和共同测试契约，冻结主框架与可支持模型。随后以 F-02/F-03/F-04 的认证输入—官方 harness—持久结果切片开始开发。进入产品适配前，由 Gate F 的实际报告决定是否放行。

本文定义开发计划；实际实现、独立验收与剩余缺口以 [实施台账](requirements/IMPLEMENTATION_TRACKER.md) 为准。新增 runtime 与集成服务分离部署，不据此切换旧运行入口或迁移现有研究结果。
