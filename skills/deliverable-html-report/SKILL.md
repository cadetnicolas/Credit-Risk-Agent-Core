# 可交付 HTML 报告的版式规范与交付加固 (`deliverable-html-report`)

本规程只管**长什么样、怎么交付、怎么维护**，不管**算什么**。业务口径、阈值与结论全部来自各工具返回的 envelope 摘要与产物文件；本规程只规定这些数字被摆到页面的什么位置、用什么组件、在什么宽度下必须仍然完整可读，以及如何被打印、分享和归档。

可执行实现是工具内的渲染层 `src/credit_agent/render/`（模块 `html_report.py`）；本规程与它一一对应。写报告时优先调用该模块，不要在每个脚本里各写一套 CSS——历史上每一次自写样式都伴随一次溢出事故。既有 HTML 报告用同目录 `scripts/` 下的加固与审计脚本处理。

版式细节（色板、组件标记、字号与间距）见 [references/layout-and-components.md](references/layout-and-components.md)。

---

## 何时使用 / 何时不使用

**何时使用（触发条件）**：
- 需要把 `profile_binning`、`screen_features`、`train_and_evaluate_candidate`、`run_portfolio_monitoring`、`decompose_and_locate_anomaly`、`simulate_policy_rules` 或 `verify_and_commit_report` 的结果交付给业务方、评审方或留档时。
- 需要把多个 run 的结论合成一份带审计链的报告时。
- 需要对已有 HTML 报告做版式修复（溢出、裁切、窄屏错乱、打印缺列）时。
- 报告是单文件交互式看板，需要补打印、深链、无 JS 兜底或键盘可达时。

**何时不使用（不得按本规程产出的情形）**：
- 只是向对话里的用户口头解释结论时——不要为了「好看」生成一份 HTML 文件。
- 数字尚未通过 `verify_and_commit_report` 核验时，不得按「已交付」版式渲染：报告里的每个数字都要能对上工具摘要。
- 需要的是可编辑文档（docx / xlsx / pptx）时，本规程不适用。

## 一、五条不可违背的版式红线

1. **任何内容都不许被裁掉**。
   禁止用 `overflow:hidden` 去「修」溢出——那只是把内容切掉。宽表一律放进横向滚动容器；长字段（特征名、run_id、路径）一律允许折行。验收标准是：页面自身不产生横向滚动（`scrollWidth == clientWidth`）。
2. **一屏之内先给结论**。
   页面顶部必须先是「标题 + 一行元信息 + KPI 卡」，再是分节论证。读者不滚动就能知道这份报告的量级与结论方向。
3. **表格可以缩，数字不能折**。
   表头允许折行，让表格缩进容器宽度；数值列一律 `white-space:nowrap` 并右对齐、等宽数字，避免 `1,234` 被拆成两行。
4. **颜色只表达语义，不做装饰**。
   红 = 风险/恶化/拒绝，绿 = 通过/改善，橙 = 需要关注，蓝 = 中性信息，灰 = 不可用。同一份报告里同一颜色不得有两种含义。
5. **报告必须能被打印和归档**。
   网页能看不等于报告能交付。打印时不得缺列、不得丢语义色、不得把提示框切断。

## 二、页面骨架

自上而下固定五段，顺序不得调整：

| 段 | 内容 | 约束 |
| --- | --- | --- |
| 页头 | 标题 + 一行元信息 | 元信息含方法、样本范围、run_id；长 id 必须折行 |
| KPI 区 | 3~5 张卡片 | 自适应网格（`auto-fit` + `minmax(170px,1fr)`），禁止写死 4 列 |
| 正文分节 | 每节一个 `<h2>`，可含子节 `<h3>` | 节内先一句导语，再上表格或卡片 |
| 结论/局限 | 用提示框逐条列出 | 每条一个提示框，标题即结论 |
| 页脚 | 数据源、账本路径、口径一行 | 字号最小，允许折行 |

页面 `<head>` 必须含 `charset`、`viewport`、`color-scheme:light` 三个 meta。缺 `viewport` 时窄屏会按 980px 虚拟宽度渲染，直接触发横向溢出。

交互报告另需：跳转正文链接、打印专用标题、`noscript` 兜底、键盘焦点可见样式。

## 三、组件清单

只用这六个组件，不得临场发明新组件：

1. **KPI 卡**：一个大数字 + 一行标签 + 一行补充说明。数字用主题色区分（风险指标用橙/红，通过类用绿）。
2. **标准表格**：必须带滚动容器；列多时用「表头名 → 列样式」声明数值列、宽文本列、标识列，而不是在单元格里散写内联样式；`<th>` 必须有 `scope="col"`。
3. **提示框**：四类语义——`info`（中性说明）、`ok`（可交付/通过）、`warn`（需关注）、`risk`（风险/阻断）。标题写成一句结论，正文写依据。
4. **特征卡**：一张卡片对应一个变量，卡头放变量名 + 系数/统计量标签，卡内放该变量的分箱表与坏率条。
5. **标签**：短状态词（已签/待签/待核/不可用/候选），只用于表格内的状态列与卡头，不得用于长句。
6. **坏率条**：表格内的相对长度可视化，宽度固定 110px 左右，按列内最大值归一，不按全表归一回。

## 四、溢出与自适应的具体规则

按发生频率从高到低：

1. **表格**：外层容器 `overflow-x:auto`，容器内 `table{width:100%}`；表格的 min-content 超过容器时在容器内滚动，页面不滚。禁止给 `table` 加 `overflow:hidden`。
2. **长标识符**：特征名、`run_xxx`、文件路径所在单元格设最大宽度（170~340px）+ `overflow-wrap:anywhere`，避免 46 字符的字段名把整张表顶宽。
3. **网格**：KPI、卡片组、双栏布局全部用 `repeat(auto-fit, minmax(基准, 1fr))`，不用 `repeat(2,1fr)` 这类固定列数——固定列数在窄屏必然溢出。
4. **代码片段**：`code` 必须 `overflow-wrap:anywhere`，否则一段长路径会撑破容器。
5. **窄屏**：≤640px 时收紧内边距与字号，表格字号降到 12px，标识列最大宽度降到 220px。
6. **Sticky 表头**：表头要吸附视口时，滚动容器必须自身可纵向滚动（`overflow:auto` + `max-height`）；仅 `overflow-x:auto` 的容器无法让 `thead` 吸附页面顶部。否则不要声称表头 sticky。
7. **打印**：见第八节，完整落地 `@page`、颜色保真与分页规则。

任何「看不全」的报障，先按上面几条定位，不要靠调小字号糊过去。

## 五、内容密度与写法

1. **每节一句导语**：说明这节回答什么问题，不超过两行。
2. **表格列数上限 8 列**：超过就拆表，或把次要列挪进特征卡。
3. **数字格式统一**：比例用百分数保留 2 位；统计量保留 3~4 位；计数用千分位；缺失一律 `—`，不要写 0 或空。
4. **结论先行**：提示框标题就是结论（「十分位不单调，低分段存在平台期」），正文才是依据（具体数字与原因）。
5. **区分事实与判断**：工具摘要里的数字是事实，必须可引用；推断与建议要写明是判断。
6. **口径必须写进报告**：标签定义、时间切分、分箱方法、样本范围、基准坏率——这些决定数字能不能横向比较，缺一项读者就会误用。

## 六、交付加固（打印 / 兜底 / 深链 / 数据 / 无障碍 / 安全）

1. **打印**：`@page{size:A4 landscape;margin:10mm}`；打印时滚动容器 `overflow:visible;max-height:none`，表格 `width:100%`，去 sticky，开启 `print-color-adjust:exact`，卡片/提示框 `break-inside:avoid`，隐藏交互工具栏，显示打印专用标题。
2. **无 JS 兜底**：`<noscript>` 至少给出可读的静态摘要（如各分支关键指标表）或明确提示，不得整页空白。
3. **深链**：交互报告的当前分支/维度/年份/指标写入 URL hash，提供「复制当前视图链接」；刷新后可还原。
4. **数据双轨**：超 500 KB 的单行内联数据拆成 `data.js` + 模板源码；交付前重新 inline 成自包含单文件。源码版便于 diff，交付版便于离线分发。
5. **无障碍**：切换控件用 `<button aria-pressed>`，排序表头补 `tabindex/role/aria-sort/Enter-Space`，表格补 `<caption>` 与 `scope="col"`，跳转链接与 `:focus-visible` 可见。
6. **安全转义**：禁止把用户可控字符串拼进 `onclick="fn('${x}')"`，改用 `data-*` + 事件委托；全字段统一 HTML 转义。
7. **字号与对比度**：辅助文字不得浅于 `#6b7582`；最小字号 11px，正文 13px 起。
8. **响应式冲突**：禁止在 KPI/网格元素上写内联 `grid-template-columns`，统一用 `auto-fit,minmax()`；已有内联样式必须用 `!important` 规则收口。

## 七、反模式清单

以下写法在本项目历史上都真实导致过「内容显示不全」或误导，禁止再用：

- 给 `table` 加 `overflow:hidden` 配 `border-radius`（切内容）。
- `td.num{white-space:nowrap}` 与 `width:100%` 同时使用却不给滚动容器（单元格溢出被裁）。
- KPI 区 `grid-template-columns:repeat(4,1fr)`（窄屏挤压、数字折行），或在 KPI 元素上写内联列数覆盖断点。
- 卡片组 `repeat(2,1fr)` 而卡片内含 6 列以上小表（卡片顶破页面）。
- 用 `min-width:240px` 标记「宽列」却不允许折行（宽列叠加后总宽超容器）。
- 只写 `<meta charset>` 不写 `viewport`。
- 同一份报告里混用两套色板（红在一处表示风险、在另一处表示强调）。
- 把分支名等数据拼进 `onclick` 字符串；用自定义 `div` 充当按钮且无键盘操作。
- 只有 JS 渲染的正文且无 `<noscript>`——禁用 JS 时整页空白。

## 九、交付前自检

1. **结构**：所有表格都在滚动容器内；页面无裸 `<table>`；`div` 开闭数量相等；`<th scope="col">` 齐全。
2. **宽度**：在 1280 / 900 / 760 三个宽度下，页面均无横向滚动；1280 与 900 下不应有表格需要内部滚动。
3. **打印**：浏览器打印预览中表格不被裁、语义色保留、提示框不跨页、交互栏不打印、打印标题出现。
4. **无 JS**：禁用 JavaScript 后页面不是空白。
5. **分享**：深链可还原视图；复制的链接可直接打开同一状态。
6. **脚本审计**：`audit_report.py` 无 FAIL；WARN 已逐条说明原因。
7. **数字**：KPI、表格、正文里出现的同一个指标必须完全一致；改动正文数字后要重新核验。
8. **口径**：标签、切分、分箱、基准坏率四项齐全。
